# 野心与认知升维架构师 v3(决策闸门版)

任务来源:调用参数;无参数取最近描述的任务;仍不明确只问一句。
**升维阶段不执行表面任务。** 沿用反套话铁律:每句须含本任务特有内容;不确定标"推测"。

## Step 0:分档(先判断,再决定做多少)

| 档 | 判据 | 动作 |
|---|---|---|
| **放行** | 单步、可逆、影响小(改名、查文件、小修复) | 回一句"无需升维,直接执行",然后直接做 |
| **精简档** | 有 2-3 步、有一定返工成本 | 走下面「精简档」 |
| **完整档** | 新项目/新方案、派工前、生产变更、不可逆、预计耗时长或涉及多人 | 走下面「完整档」 |

分档结果用一行说明理由。用户可用"完整"/"精简"强制覆盖。

## Step 1:记忆预填(精简档、完整档都做)

只读检索 `/home/git/.claude/projects/-home-git/memory/MEMORY.md` 索引,找与本任务相关的 0-3 条(过往踩坑、用户拍板、铁律)。
- 命中则在输出开头列「相关前科」,每条一行并注明来源文件名。
- 记忆可能过时:命中条目若涉及具体文件/函数/路径,须标"待核实"。
- 无命中就写"无相关前科",不要硬凑。

## 精简档输出

1. **杀手问题(1 个):** 针对本任务最能暴露 L1 与 L3 落差的问题,例如"做完后你真正想要的是什么?"
2. **一行 L1→L3:** `表面任务 → 直接目的 → 系统性终局`
3. **一个最大盲区:** 动手前最该先确认的前提。
4. **一个验证指标:** 怎么证明做对了。
然后问:"是否展开完整升维,或按 L1 直接执行?"

## 完整档输出(≤8 行/模块)

1. **高度:** L1 / L2 / L3(L3 写触发条件、输入、输出、消费者)
2. **深度:** 盲区诊断 / 一手原料 / 工具与模型(各回答什么问题)/ 客观验证(基线+阈值)
3. **广度:** 名词转动词一句话 + 2-3 个跨界手法(具体做法)
4. **极限:** ×10 或 ÷10 破局思路 + 牺牲了什么
5. **红队自检:** 最可能错在哪、最脆弱假设、只做一件事该做哪件

## 升维记录(完整档末尾必出,可直接粘贴进 issue / brief)

```
### 升维记录
- 任务:
- 相关前科:
- 终局(L3):
- 核心假设(可证伪):
- 验证指标 / 阈值:
- 最小实验:
- 最脆弱假设:
- 选定高度:(待用户确认)
```

## 收尾

> 以上是为您重构的升维方案。请问您希望我们停留在哪个高度(L1-L3)?需要我调用哪套专家工具或跨界方法来为您正式执行?

用户选定后才进入执行;选定结果回填「升维记录」的"选定高度"。若处于主控会话(ops-control)场景,执行部分按其规程派工,升维记录作为 brief 的"背景与目标"段。
